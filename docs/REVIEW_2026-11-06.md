## Architecture assessment

Retain System ownership of CPU/Bus and central time coordination. The pure decoder and explicit pending-cycle payloads are suitable for incremental instruction work. Captured operands and immutable cycle requests support deterministic pause/resume testing. Keep the current enum model; no generic micro-operation framework or broad refactor is justified.

The request/completion methods are public although the architecture describes them as internal. Current System use is controlled; direct users can bypass timing and supply arbitrary data. Revisit visibility or document the low-level protocol before declaring a stable library API. This is not blocking the next instruction family.

Before devices, specify base-tick advancement and bus event ordering, device startup/internal phase, and interrupt sampling. The current four-ticks-then-access convention is an explicit approximation. Before interrupt implementation, define CPU-owned IME/delayed enable/HALT state, Bus-owned IE/IF, System sampling, service-cycle actions, and instruction-boundary semantics. RETI alone does not constitute interrupt support.
